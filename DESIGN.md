## Overview

The site for the mountain expedition bureau "Шаг за перевал" ("A Step Over the Pass") — a warm, muted palette (cream/charcoal/terracotta), a handwritten logo, lots of breathing room, and no chasing trendy effects (shadows, blur, gradients are almost never used). The design leans on Tailwind's default scale (spacing, rounded, font-size) wherever possible — custom tokens exist only where Tailwind's default scale genuinely wasn't enough (see `src/app/globals.css`).

## Colors

The palette is built on a "warm cream / dark charcoal" pair plus a terracotta accent.

- **cream-100 … cream-800** — not isolated shades but a single scale (the `cream` hue, lighter toward 100, darker toward 800). `cream-100` is the base background for light pages and the text color on dark backgrounds; `cream-400/500/600/800` are muted text/borders on a dark (`charcoal`) background instead of `opacity` (see Do's and Don'ts).
- **charcoal** — the primary dark background (Hero, Footer) and the primary text color on light backgrounds.
- **terracotta** — the single bright accent; used sparingly (logo on a light background).
- **sand / taupe / walnut / ash** — supporting tones in the same range; `taupe`/`ash` are currently used as muted navigation text on light/dark backgrounds respectively (`ash` is also used as the muted mono label in `ReviewCard`), `sand` is the background of the review card in `ReviewCard` and of the whole `Team` section, `walnut` is `Badge`'s `"creamGlass"` variant text.

## Typography

Three fonts, three distinct roles — never mixed within a single text block:

- **Onest** (`font-sans`) — the default font for all UI (navigation, body text). Set on `<body>`, so it doesn't need to be specified explicitly in most components. Body text is responsive: `text-base` on mobile, `md:text-lg` on desktop.
- **Source Serif 4** (`font-serif`) — headings/large accent text only (the trip title in Hero, mobile menu items).
- **JetBrains Mono** (`font-mono`) — labels only: dates, copyright, social links — always paired with `uppercase` and increased `tracking` (`wider`/`widest`).

## Layout

The container (`src/components/Container.tsx`) — `max-w-7xl` with adaptive horizontal padding (`px-4 md:px-6 lg:px-10`); there's a `fullWidth` mode with no width cap (used in the header/hero, and as `Gallery`'s own carousel viewport — see below). `Container` accepts `ref` as a plain prop (React 19's native ref-as-prop; no `forwardRef` needed), so a caller can wire it straight to something like an `embla-carousel-react` viewport ref instead of wrapping it in an extra `div`. Vertical and horizontal spacing comes only from Tailwind's default scale — there's no custom spacing scale in the project.

Where a responsive gap is needed between grid or flex items, the sitewide step is `4 → md:6 → lg:10` (16/24/40px) — the same scale as `Container`'s own padding. Used by the `UpcomingTrips`/`TripsPage` `TripCard` grids (`gap-4 md:gap-6 lg:gap-10`) and by the `Reviews`/`Gallery` carousel gap technique (see below) alike.

On the trip page's labeled sections (`About`, `Program`, `Map`, `Team`, `Price`, `Faq`), a `SectionLabel` is always followed by `mb-4` — the gap to whatever comes next (a lead paragraph, an `h2`, a price number) is consistently `16px` regardless of what that next element is. When the `h2` right after it is itself followed directly by more section content — a photo (`Map`), a member grid (`Team`), an FAQ list (`Faq`) — that `h2` gets its own `mb-12`, not whatever margin the mockup happened to use for that specific heading. `Program`'s `h2` is the one exception: it sits in a flex row next to a meta line rather than stacking above more content, so the spacing role there belongs to the row's own wrapper margin instead.

Sections across the site (except `Hero`, which has its own full-screen layout) share a single vertical rhythm, `py-16 md:py-24` (`Manifest`, `UpcomingTrips`, `Reviews`, `Cta` on the home page; `TripsPage`, `ContactsPage`, the trip page's `About`).

## Elevation & Depth

Flat design — shadows, blur, and depth are never used anywhere. Sections are separated by background color (`charcoal` vs `cream-100`) and a thin border (`border-t` on `cream-800`), not by shadow.

## Shapes

Sharp corners by default — `rounded` is barely used. Two deliberate exceptions:
- `rounded-full` — the slider dot indicators in Hero, the circular prev/next buttons of the review carousel in `Reviews`.
- `rounded-md`/`rounded-lg` — interactive controls and photo/content cards: the button in Cta, the region badge and the card itself in `TripCard`, the review card in `ReviewCard` (`rounded-lg` for photos/cards, `rounded-md` for small elements over a photo — the same radius as the button).

## Components

- **Header / HeaderHome** — fixed height (`h-17`), logo + navigation; the logo isn't duplicated on the home page (there's already a large one in Hero), the header itself is transparent over the photo. Both use `HeaderMobileMenu` below `lg`, with `variant="dark"` on `HeaderHome` (`Header`'s default `variant="light"` matches its solid light background) — only the trigger button's icon color changes; the popover panel itself is always `cream-100`/`charcoal` since it covers the full screen and the page behind it is no longer visible.
- **HeaderMobileMenu** (`src/components/HeaderMobileMenu.tsx`) — a full-screen `popover="auto"` panel; open/close/Escape/outside-click on the trigger button are native (no JS state), no open/close animation (native popover fade transitions turned out unreliable across browsers, so the panel just snaps open/closed). Nav links do need JS: they navigate via `router.push` wrapped in `startTransition`, and a `useEffect` watching `isPending` calls `hidePopover()` the moment it flips back to `false` — i.e. the menu closes exactly when the new route has actually rendered, not after a guessed delay. This only works within a layout that keeps rendering `HeaderMobileMenu` across the navigation (e.g. between two `(pages)` routes); navigating to a different layout unmounts it immediately regardless. Nav links get the sitewide `hover:underline hover:decoration-[--underline-thickness]` pairing too, but at `underline-offset-8` instead of the usual `underline-offset-4` — at this link's large size (`text-4xl`) the standard offset sits close enough to the baseline that the line crosses descenders (у, р), reading as thicker/merged; the larger offset clears them.
- **Navigation** — the active link is underlined and in full color (`charcoal`/`cream-100`), the inactive one is a muted solid color (`taupe`/`cream-400`), **not** via `opacity`.
- **Footer** — a dark (`charcoal`) section; the same muted-text logic via `cream-400/500/600/800`, never via `opacity`.
- **Hero** — a full-screen section with a cross-fade of trip photos (an `opacity` transition on a timer), a centered logo, a darkening gradient only in the bottom half of the frame for text legibility below.
- **Manifest** — the "About us" section on the home page: a mono label (`О нас`), a large serif tagline with `text-balance` — this is the **lead/tagline** tier (`text-3xl leading-tight font-medium md:text-5xl`), separate from the "big h2" below.
- **SectionLabel** — a section's mono label (terracotta, `uppercase`, wide tracking); the bottom margin is set from outside via `className` since it varies (16/20/24px) in the design.
- **Badge** (`src/components/Badge.tsx`) — the small mono pill used over photos (region on `TripCard`, dates/format on the trip page's `Hero`): `rounded-md px-3 py-1.5 font-mono-tight text-xs font-bold uppercase`, `variant="terracotta"` (default) or `"charcoal"`. Positioning (e.g. `absolute top-4 left-4` on `TripCard`) is passed in via `className`, not baked into the component, since it differs by context.
- **`font-mono-tight`** (custom utility, `src/app/globals.css`) — `font-family: var(--font-mono)` + `letter-spacing: var(--tracking-wider)` + `word-spacing: -0.4em`, defined via Tailwind v4's `@utility` at-rule so it behaves like any built-in utility (composes with `text-*`/color/etc., no `cn()` ordering concerns). Exists because JetBrains Mono's space glyph is fixed-width like every other character, and tracking's `letter-spacing` stacks on top of it — multi-word mono text (a date range, a meta line) reads with noticeably wider gaps between words than between letters within a word unless something pulls the words back together; `word-spacing` is the property for exactly that, scaled in `em` so it stays proportional at any font-size. This is now the sitewide replacement for plain `font-mono` — every mono-text callsite uses it (`Badge`, `Button`, `SectionLabel`, `Footer`, `TripCard`, `UpcomingTrips`'s "Все путешествия", `ReviewCard`, home `Hero`'s date, the trip page's `Hero` stat row/`Quote`/`Program`, `ContactsPage`'s social links), including single-word text — `letter-spacing`/`word-spacing` are harmless on a lone word, and one recipe for "mono label" is simpler to reason about than two. `Navigation`'s nav links are the one sitewide exception, since those are `font-sans`, not mono.
- **Button** (`src/components/Button.tsx`) — the filled CTA (`Cta`'s "Выбрать путешествие", the trip page `Hero`'s "Присоединиться"): `bg-terracotta text-cream-100 font-mono-tight rounded-md px-9 py-4 text-base font-bold uppercase transition duration-200 ease-out hover:brightness-110`. Renders a `Link` when given `href`, otherwise a native `<button>` — same visual component either way, so a future form submit button doesn't need its own copy. Typed as a discriminated union on `href` (not just `href?: string` on one shared prop bag): pass `href` and you get `Link`'s props and TS requires it as a string; omit it and you get native `<button>` props (`type`, `disabled`, `onClick`, …) instead — so e.g. `href` + `disabled` together is a type error, not a silently-ignored combination. The design also has an outline/pill secondary visual style ("Подробнее" on a trip card) and a `size` axis may come later — neither exists here yet, since nothing in the app uses them. Note `variant` is reserved as the name for a future render-*kind* discriminant (see the `INFO:` comment in `Button.tsx` — link vs. button vs. a hypothetical third kind), not for the visual style; the outline/pill style will need a different prop name whenever it's actually built.
- **"Big h2"** — the section-heading tier, larger than the lead tagline: `font-serif text-4xl font-medium md:text-6xl` (no `tracking-*` — default tracking; `tracking-tight` at this size caused the serif glyphs to collide). Used in `Cta` ("Готовы к приключениям?") and `UpcomingTrips` ("Ближайшие путешествия") — anywhere a section heading stands on its own rather than pairing with a tagline paragraph the way `Manifest` does.
- **Page `<h1>`** — one tier above "big h2", reserved for a page's own `<h1>` (the design goes up to 90px, bigger than any in-page section heading): `font-serif text-5xl font-medium md:text-8xl`, same no-`tracking-*` rule. Used in `TripsPage`, `ContactsPage` on this breakpoint-jump form, and the trip page's `Hero` — including there even though its design mockup went bigger (up to 120px): kept it to one page-`<h1>` tier sitewide instead of introducing a second, larger one just for that page. `Hero`'s `<h1>` uses the same bounds but fluidly, like `Quote`'s text (see below) — `text-[clamp(var(--text-5xl),9vw,var(--text-8xl))] leading-none` — since it's the one page `<h1>` that shares its section with a full-bleed photo where an abrupt breakpoint jump is more noticeable. Any arbitrary `text-[clamp(...)]` value needs an explicit `leading-*` alongside it: Tailwind's named size utilities (`text-5xl`, `text-8xl`, …) each carry a paired `line-height` from the theme (here, `1` for both ends), but an arbitrary bracket value only sets `font-size` — pairing is lost, so line-height silently falls back to whatever's inherited unless restated.
- **TripCard** (`src/components/TripCard.tsx`) — a reusable trip photo card (used in `UpcomingTrips` on the home page and in the `/trips` grid): `aspect-[3/4]`, `rounded-lg`, a darkening gradient at the bottom for legibility — the same `color-mix(in oklch, var(--color-charcoal) N%, transparent)` technique as the gradient in the home page's `Hero`, but one-sided (bottom to top, no darkening at the top), a region `Badge`, a heading `text-3xl md:text-4xl font-serif font-semibold` (30→36px, closer to the design's 34→46px than the "trip title" tier from the home `Hero`) — smaller than both the section's "big h2" and the active trip title there, dates/price use the same `font-mono-tight text-sm font-bold uppercase` pairing as the dates in the home `Hero`. Hover: the photo is muted by default (`saturate-50`), "comes alive" with color on hover (`saturate-100`) and zooms in slightly (`scale-110`) — plain CSS (`group`/`group-hover`, `transition-all duration-700`), no JS.
- **UpcomingTrips** — the "Ближайшие путешествия" section on the home page: the heading is the "big h2" (see above), the "Все путешествия" link reuses the `SectionLabel` pairing (`font-mono-tight`/bold/uppercase) but smaller (`text-sm`) and terracotta; the card grid is `grid-cols-1 gap-4 sm:grid-cols-2 md:gap-6 lg:grid-cols-3 lg:gap-10` (see the gap scale note under Layout above).
- **ReviewCard** (`src/app/(home)/_components/ReviewCard.tsx`, page-only — used only in `Reviews`) — a review card: `bg-sand`, `rounded-lg`, `p-9`; avatar `h-13 w-13 rounded-full`, name `text-base font-bold`, trip — a mono meta label (`text-ash font-mono-tight text-xs uppercase`), quote — `font-serif text-xl font-medium leading-normal text-balance`, wrapped in «» directly in the markup (not in the content).
- **Reviews** — the "Отзывы" section on the home page: two `Container`s in a row — a regular one (`max-w-7xl`) under the heading and prev/next buttons, followed by a `fullWidth` one that doubles as the carousel's own embla viewport (its `ref` wired straight to `emblaRef`, `overflow-hidden` in its `className` — see the `ref`-as-prop note under Layout above — so only the track bleeds to the screen edge, not the section header, with no extra wrapping `div` needed). The heading is the "big h2" (see above) on the same line as the circular prev/next buttons (`items-baseline`, as in `UpcomingTrips` — the buttons don't drop below the heading's baseline). The carousel uses `embla-carousel-react` with no plugins (`align: 'start'`, no loop — the prev/next buttons dim (`disabled:opacity-40`) at the edges; swipe/drag out of the box, the track is `select-none` so dragging doesn't select card text, plus `will-change-transform`; no autoplay or fade — removed as unused dependencies). The gap between slides follows embla's official pattern (a negative `margin-left` on the track plus `padding-left` on each slide, `-ml-4/pl-4` → `md:-ml-6/pl-6` → `lg:-ml-10/pl-10`, the same steps as `Container`'s padding), **not** `gap` on the flex container — `gap` combined with a percentage `flex-basis` rounds unpredictably and breaks embla's `align: 'start'` alignment (a slide would sometimes sit flush, sometimes get clipped on the left). Slide width is `flex-[0_0_100%] md:flex-[0_0_50%] lg:flex-[0_0_33.333%]` with a `max-w-md` ceiling (keeps a card from growing too large on very wide screens in the fluid track).
- **Cta** — a dark (`charcoal`) "Готовы к приключениям?" section with a terracotta button linking to `/trips`; text on the dark background uses named tiers (`cream-400`), not `opacity`.
- **TripsPage** (`src/app/(pages)/trips/page.tsx`) — the `/trips` listing: `SectionLabel` ("Календарь") + the page's own `<h1>` on the "Page `<h1>`" tier (see above) + an intro paragraph (`text-taupe`, `max-w-prose` — Tailwind's default ~65ch measure, close enough to the design's 60ch to skip a custom value), then the same `TripCard` grid as `UpcomingTrips` (`grid-cols-1 gap-4 sm:grid-cols-2 md:gap-6 lg:grid-cols-3 lg:gap-10`).
- **ContactsPage** (`src/app/(pages)/contacts/page.tsx`) — `SectionLabel` ("На связи") + the page's own `<h1>` (see above) + email/phone as `text-2xl font-semibold` links, then the same social-links recipe as `Footer` (`font-mono-tight text-xs uppercase`, `hover:underline hover:underline-offset-4`). Content comes straight from `siteContact`/`socialLinks` in `src/content/site.ts`.
- **Hero** (`src/app/(pages)/trips/[slug]/_components/Hero.tsx`, page-only — not to be confused with the home page's own `Hero`, `src/app/(home)/_components/Hero.tsx`, a different component that happens to share the name since each lives in its own page-scoped `_components` folder) — the cinematic full-photo hero for a trip's own page: `min-h-[calc(100dvh-(--spacing(17)))]` — Tailwind v4's `--spacing(N)` function shorthand for "N steps of the theme's base spacing unit" (`0.25rem`, `node_modules/tailwindcss/theme.css`), i.e. exactly what `h-17` itself computes to; referencing it directly keeps this tied to `Header`'s `h-17` step instead of a hardcoded `4.25rem` that just happens to match today; `min-h-`, not a fixed `h-`, so a trip with a longer title/more content grows the section instead of clipping against `overflow-hidden`), content pinned to the bottom (`flex flex-col justify-end`), a bottom-only darkening gradient (same `color-mix` technique as the home `Hero`/`TripCard`), a `Container fullWidth` (unlike `TripsPage`/`ContactsPage` — the design's hero content isn't capped at `max-w-7xl`, only padded), two `Badge`s (dates + trip format, `terracotta`/`charcoal` variants), the "Page `<h1>`" tier (see above) at `w-full` on mobile widening the wrap to use all the available space, capped to `md:w-1/2` of the container from `md` up with `text-balance` so a long title wraps onto a couple of even lines instead of running the full width, then a stat row (days/km/price, `font-mono-tight text-lg font-bold md:text-2xl` values over `text-sm uppercase text-cream-400 md:text-base` labels — `font-mono-tight` sits on the row's wrapper rather than each value/label individually, so both inherit the font/tracking/word-spacing without repeating it, `gap-5 md:gap-8` between the three — all three step down together below `md` since at the mobile width this row sits under the same photo as the "Page `<h1>`" tier's already-large title) plus a "Присоединиться" button reusing `Cta`'s exact button recipe, currently linking to `/contacts` (no application-form section yet). `TripPage` (`/trips/[slug]`) is meant to grow more sections over time, and not every trip is expected to use every section: a section whose data on `TripDetail` is optional (e.g. `map`) is responsible for rendering nothing (`return null`) when that data is absent, rather than the page filtering sections in or out — see `Map` below for the pattern.

- **About** (`src/app/(pages)/trips/[slug]/_components/About.tsx`, page-only) — the "О маршруте" section of a trip's own page, directly below `Hero`: a `SectionLabel` (the design mockup's own section labels are numbered, "01 — О маршруте"/"02 — Программа"/etc.; the number is dropped sitewide since it would go stale once a section can be absent per trip — see the `TripPage` note under `Hero` above), a lead paragraph on the same tier as `Manifest`'s heading (`font-serif text-3xl leading-tight font-medium text-balance md:text-5xl`, `max-w-2xl`), a `md:grid-cols-3` grid of body paragraphs (`text-taupe`, `gap-5 md:gap-10` — the mobile gap is half the desktop one since a single narrow column reads fine tighter, unlike the 3-up desktop grid), then a photo strip that reflows by breakpoint rather than just resizing the same grid: on mobile `grid-cols-2` with the first photo spanning both columns above the other two (`aspect-16/9` for that first photo, `aspect-4/3` for the rest), on `md+` the desktop-only `grid-cols-[1.6fr_1fr_1fr]` asymmetric wide-then-two-narrow row (`md:h-96 md:aspect-auto` — a fraction ratio with no equivalent in Tailwind's default scale, unlike spacing/color/radius/font-size, kept as an arbitrary value), `rounded-md`, `gap-4`.

- **Quote** (`src/app/(pages)/trips/[slug]/_components/Quote.tsx`, page-only) — the standalone pull-quote section directly below `About`. `trip.quote` is optional; `Quote` returns `null` when absent, the same optional-section pattern documented under `Map` below. A centered `Container` capped to `max-w-4xl` (narrower than the site's usual `max-w-7xl`, overridden via `className` per `Container`'s own convention), an attribution line in `text-ash font-mono-tight text-sm text-balance uppercase md:text-base` (steps down on mobile, same reasoning as the `Hero` stat row below; `text-balance` alongside the quote text's own, so a name + org line doesn't leave a single orphan word on its own line). Its top padding matches the site rhythm (`pt-16 md:pt-24`) but the bottom is doubled (`pb-32 md:pb-48`) — an asymmetric gap that gives the quote more room to breathe before `Program`'s dark section below, closer in spirit to (if smaller than) the design mockup's own lopsided 140px/220px padding for this section.

  Both the opening `«` and the quote text itself use a fluid `clamp()` font-size instead of a breakpoint jump — the only two places on the site doing this (besides `Hero`'s `<h1>` below): `«` is `text-[clamp(var(--text-5xl),8vw,var(--text-7xl))]`, the quote text is `text-[clamp(var(--text-2xl),4vw,var(--text-5xl))] leading-tight font-medium text-balance`. In both cases the min/max bounds are Tailwind's own theme variables rather than hardcoded px from the mockup's `clamp(28px, 3.6vw, 46px)`, so they still snap to the type scale at both ends and only the middle scales continuously with viewport width. No `length:` type hint needed in the arbitrary value — Tailwind infers `font-size` correctly from `clamp(...)` on its own since it doesn't resemble a color. Note: an arbitrary `text-[clamp(...)]` value only sets `font-size` — unlike named utilities (`text-5xl`, etc.), it doesn't carry a paired `line-height` from the theme, so pair it with an explicit `leading-*` when the named tier it's replacing had one (see `Hero`'s `<h1>` below, which needs `leading-none` for exactly this reason; `«` also has it, the quote text's `leading-tight` was already explicit before switching to `clamp()`).

- **Program** (`src/app/(pages)/trips/[slug]/_components/Program.tsx`, page-only) — the "Программа" day-by-day itinerary directly below `Quote`, and the first `charcoal` section on the trip page (`bg-charcoal text-cream-100`, matching `Program`'s design-mockup background rather than the page's usual `cream-100`): a `SectionLabel` + the "big h2" tier ("По дням"), paired on the same row with a right-aligned meta line (`{days} дней · {distance} км · {dates}`, composed straight from `trip.hero` rather than duplicated in `trip.program` — nothing about it varies independently of the hero stats) in `text-cream-600 font-mono-tight text-sm uppercase md:text-base`. Each day is a row — `grid-cols-1` on mobile (stacked), `md:grid-cols-[210px_1fr_1.3fr]` (day label / place / description) from `md` — separated by `border-cream-800` (the same subtle-divider token as the `Elevation & Depth` section-boundary convention, chosen over `cream-400` because the mockup's divider opacity, .16, is much closer to that established "barely-there" tier than to `cream-400`'s ~25%-opacity-equivalent "muted but visible" one). Within a row: the day label (`День N`, `text-terracotta font-mono-tight text-base font-bold uppercase`, tags below it stacked one per line (`flex flex-col gap-1`) in `text-cream-600 font-mono-tight text-xs uppercase`), the place as an `h3` (`font-serif text-2xl font-semibold`, the same recipe as `TripCard`'s heading), and the description in `text-cream-400 leading-relaxed` — `cream-400`/`cream-600` mirror `Footer`'s own two-tier muted hierarchy on `charcoal` (body text vs. copyright), reused here instead of inventing a third convention for "muted text on dark."

- **Gallery** (`src/app/(pages)/trips/[slug]/_components/Gallery.tsx`, page-only) — the unlabeled photo-slider section directly below `Program` (the design mockup gives it no section label at all, unlike every other section on the page). `trip.gallery` is optional; `Gallery` returns `null` when it's absent or empty, the same optional-section pattern documented under `Map` below — the guard sits after the `useEmblaCarousel`/`useEffect` hook calls, not before, since hooks can't be called conditionally. `embla-carousel-react`, `align: 'center'` (`Reviews` uses `'start'` — `Gallery`'s slides center in the viewport rather than pinning to the left edge), no loop, the same circular prev/next buttons dimming via `disabled:opacity-40`. `Container fullWidth` doubles as the embla viewport itself here (`ref` wired straight to it — see the `ref`-as-prop note under Layout above — with `overflow-hidden` in its own `className`), instead of `Reviews`'s separate inner `div` for that role. The gap technique matches `Reviews` exactly: `-ml-4 md:-ml-6 lg:-ml-10` on the track, `pl-4 md:pl-6 lg:pl-10` per slide, instead of `gap` (see `Reviews` above for why), `select-none`/`will-change-transform` on the track. Per-slide sizing is its own, since a slide here is only ever a photo rather than `Reviews`'s content-sized card: `flex-[0_0_100%] sm:flex-[0_0_50%]`, capped with the same `max-w-md` `Reviews` uses — one slide per view below `sm` (640px), two from `sm` on, with no further step to a three-up tier at `lg` the way `Reviews`/`TripCard` grids do; two photos is the ceiling at any width. Each slide is `rounded-lg`, `aspect-square md:aspect-16/10` — square through the one-per-view and two-up tiers, a wide landscape crop from `md` once slides have more room to work with — with the photo as a `fill` `Image` (`sizes="(min-width: 640px) 50vw, 100vw"`), no caption over the photo (the `alt` text alone carries each photo's description).

- **Map** (`src/app/(pages)/trips/[slug]/_components/Map.tsx`, page-only) — the "Маршрут" section directly below `Gallery`, the simplest section on the page: a `SectionLabel` + the "big h2" tier ("Карта маршрута", `mb-12` — the design mockup's own 48px gap before the map, matching Tailwind's scale exactly) and a single photo (`trip.map.photo`, currently a placeholder illustration reused across all three trips, same as `Hero`'s photos). `trip.map` is optional on `TripDetail` — no trip currently has it, and `Map` returns `null` when it's absent instead of `TripPage` deciding whether to render the component; this is the reference implementation of the optional-section pattern noted under `Hero` above, to copy for any other section whose content later becomes optional. The one photo on the site not using `next/image`'s `fill`/`object-cover` pattern: instead of a `relative`-positioned box with a set aspect ratio, `Image` gets the placeholder's real intrinsic `width={2752} height={1536}` and just `h-auto w-full rounded-lg` — a plain fluid image, exactly as wide as its container with height following automatically from those attributes, no CSS aspect ratio needed and nothing ever cropped at any viewport width. This only works because the photo is never art-directed/cropped for the section (unlike, say, `TripCard`'s `aspect-3/4` treatment) — if that's ever needed here, this would have to go back to the `fill`/`object-cover` pattern.

- **Team** (`src/app/(pages)/trips/[slug]/_components/Team.tsx`, page-only) — the "Команда" section directly below `Map`. `trip.team` is optional; `Team` returns `null` when it's absent or empty, the same optional-section pattern documented under `Map` above. A `SectionLabel` + the "big h2" tier ("Ваши проводники", `mb-12`), then a `grid-cols-1 md:grid-cols-2` grid of team members (`gap-x-12 gap-y-10` — the mockup's own `40px 48px` grid gap, an asymmetric row/column pair rather than one value, so `gap-x`/`gap-y` instead of a single `gap-*`). '#f2ede3' : '#e9e3d7'`, default `flatSections: false`) to `#e9e3d7`, which is exactly this project's existing `sand` (already `ReviewCard`'s background) — the mockup markup's own `var(--panel,#f0f0f0)` fallback is misleading here since the var is always actually set from `panelBg`, never falling back to `#f0f0f0`. - **Price** (`src/app/(pages)/trips/[slug]/_components/Price.tsx`, page-only) — the "Стоимость" section directly below `Team`: `grid-cols-1 xl:grid-cols-[0.85fr_1.3fr] items-start gap-12` — a wide breakpoint gap before the two-column split, since the left column's big price number and the right column's two include/exclude lists both need real room before sitting side by side without cramping. Formatting it dynamically via `Intl.NumberFormat('ru-RU', { style: 'currency', currency: 'RUB' })` (which produces the same `U+00A0` spacing) was discussed and deliberately deferred — revisit if/when price ever needs real currency conversion or locale formatting.

Each `<details className="group">` holds a `<summary>` (`cursor-pointer select-none`, native disclosure marker hidden via `list-none` + the Safari-specific `[&::-webkit-details-marker]:hidden` arbitrary variant, since Tailwind has no built-in utility for that pseudo-element) laying out the question (`text-2xl font-semibold`, plain `font-sans` rather than `font-serif` — a deliberate choice, unlike the same-tier heading elsewhere on the page like `Program`'s day-place or `Team`'s member name) against a `lucide-react` `PlusIcon` that turns into a "×" via `group-open:rotate-45` (Tailwind v4 targets the CSS `rotate` property directly here, not `transform` — `getComputedStyle(el).transform` reads `none` even when rotated; check `.rotate` instead) — zero JS, driven entirely by the native `<details open>` state. Multiple items can be open at once (no `name`-attribute exclusivity grouping) — deliberate, matches native `<details>` default behavior rather than adding complexity for single-open-at-a-time.

## Content: preview vs. detail

`src/content/trips.ts` (`Trip`) and `src/content/tripDetails.ts` (`TripDetail`) are deliberately separate, even though right now they're both static arrays with overlapping placeholder data. `Trip` is the lightweight shape used for listing UI (`TripCard`, `UpcomingTrips`, `TripsPage`'s grid) — id, slug, title, region, dates, price, photo. `TripDetail` is the full shape a trip's own page needs, looked up by `slug` alone (no `id`/`region` yet, since nothing on the detail page needs them). This split exists because the two will eventually come from two different API calls (a list endpoint vs. a per-slug detail endpoint) — the listing page was never meant to fetch full detail data for every trip just to render a card.

`TripDetail` itself is grouped by page section (`hero`, `about`, `quote`, `program`, `gallery`, `map`, `team`, `price`, more as the page grows) rather than kept flat — each page-only section component (`Hero`, `About`, `Quote`, `Program`, `Gallery`, `Map`, `Team`, `Price`) reads only its own nested object off `trip`, so a section's fields stay scoped to the component that uses them instead of one flat bag everyone reads from. `slug`/`title` stay top-level since they identify the trip as a whole rather than belonging to one section. Each day in `program.days`, each photo in `gallery`, and each member of `team` gets its own sequential `id` (same convention as any other enumerable content array) since `place`/`caption`/`name` aren't guaranteed unique the way they are here only by coincidence of today's placeholder data.

## Do's and Don'ts

- **Don't** use `text-{color}/NN` (an opacity modifier) for muted text on a known solid background — set up/use a named scale tier instead (`cream-400`, etc.). This project's experience: semi-transparent text is equivalent to an eyeballed hardcoded color and doesn't scale to new components.
- **Don't** add a custom token (color/spacing/radius) when a value from Tailwind's default scale already fits — see `AGENTS.md`.
- **Don't** write a utility class that equals the CSS default value (`tracking-normal`, `font-normal` when it's already inherited) — if a tier turns out to be the default, just drop the class instead of writing it out explicitly (example: the "big h2" has no `tracking-*`, see Components).
- **Do** keep the three fonts strictly to their roles (sans — UI, serif — headings, mono — labels/dates), never mixed within one semantic block.
- **Do** use `cn()` (`src/utils/cn.ts`) whenever merging classes where the base classes might be overridden from outside via `className`.
- **Do** give every button's hover transition the same timing — `duration-200 ease-out` (`Cta`'s link-button, the prev/next buttons in `Reviews`) — so hover feedback feels consistent across controls.
- **Do** use the sitewide `4 → md:6 → lg:10` step (16/24/40px) for a responsive gap between grid/flex items — matches `Container`'s own padding scale (see Layout above).
